## Reporting Bugs & Requesting Features

Use the structured forms when [opening an issue](https://github.com/rossijonas/stamp/issues/new/choose):

- **Bug report** — include your `stamp --version`, OS and distribution, the package manager involved, and the output of `stamp doctor --json`. Redact tokens, API keys, and personal paths.
- **Feature request** — describe the problem and the behavior you would like.

## Security

Do not report vulnerabilities in a public issue. Follow [SECURITY.md](https://github.com/rossijonas/stamp/blob/main/SECURITY.md) to report privately through GitHub Security Advisories.

## Support

See [SUPPORT.md](https://github.com/rossijonas/stamp/blob/main/SUPPORT.md) for where to ask questions versus report bugs versus report security issues. Documentation lives at [gostamp.dev](https://gostamp.dev).

## Issue Labels

Used to triage incoming reports:

| Label | Meaning |
| ----- | ------- |
| `bug` | Confirmed or suspected defect |
| `enhancement` | New feature or improvement request |
| `needs-triage` | Awaiting initial review by a maintainer |
| `question` | Further information requested |
| `documentation` | Documentation improvement |
| `good first issue` | Suitable for newcomers |
| `help wanted` | Extra attention needed |
| `security` | Security-related |
| `P1` / `P2` / `P3` | Priority, highest to lowest |
